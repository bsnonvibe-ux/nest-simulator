## Issue #3744
Баг: при сбросе симуляции (`ResetKernel`) настройки — куда сохранять файлы (`data_path`) и с каким префиксом имени (`data_prefix`) — должны сбрасываться в пустые строки, а на деле оставались от предыдущего запуска.

Причина: код собирал список настроек для применения только из переменных окружения — если переменная не задана, настройка просто не попадала в список вообще, а не "передавалась как пустая". А функция, которая применяет список, обновляет только то, что реально в списке есть — то, чего в списке нет, просто не трогает. Раз "путь не задан" не значит "путь = пустая строка" для этого кода, старое значение так и оставалось висеть.

## Развилка (обсудили, выбрали вариант 1)
Починка "в лоб" (всегда класть в список пустую строку, если переменной нет) сама по себе создавала новую проблему: код, который применяет `data_path`, пытается "открыть папку" с этим именем, чтобы проверить, что она существует — а для пустой строки такая проверка закономерно проваливается, и в лог при каждом сбросе сыпалась бы ошибка, даже в самом obычном сценарии без всяких переменных окружения.

Добавил отдельную обработку: пустая строка — это не "папка, которую надо проверить", а "настройка сброшена, ничего проверять не нужно". Это чуть больше кода, чем буквально просят в issue, но без этого фикс работал бы криво. В комментарии в коде явно отметил, что это усовершенствование сверх минимального фикса.

## Проверка
- Прогнал ровно пример кода из issue: `('', '') -> ('.', 'foo') -> ('', '')` — совпадает с ожидаемым.
- Проверил, что старое поведение цело: несуществующая папка по-прежнему честно ругается ошибкой, реальная папка принимается тихо, префикс с "/" внутри по-прежнему запрещён.
- C++ тесты (`run_all_cpptests`): 29 из 29 прошли.
- Python-тесты (весь `installcheck`): 4668 прошли, 5 упало — но эти 5 никак не связаны с моей правкой (несовместимость версии scipy с одним конкретным статистическим тестом генератора случайных чисел, падают из-за версии библиотеки, а не из-за кода NEST). Прогнал их отдельно, убедился, что причина падения — внутри scipy, не в `io_manager.cpp`.
- Добавил отдельный регресс-тест `testsuite/pytests/regressions/test_issue_3744.py` — по стандарту самого проекта (у них тесты на конкретные issue называются по номеру).
